# Creative Canvas Hub

Portfolio and admin CMS built with React, TanStack Start, and MongoDB/Mongoose.
Admin image uploads are sent to the authenticated server API and stored in
Cloudflare R2; MongoDB stores their public URLs and metadata.

## Local development

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env` and fill in the existing MongoDB, JWT, and admin
   values.
3. Configure the Cloudflare R2 values below.
4. Start the app with `npm run dev`.

The R2 credentials are read only by server code. Do not add `VITE_` to any R2
variable, expose them in client code, or commit `.env`.

## Cloudflare R2 setup

1. In Cloudflare, create an R2 bucket for portfolio images.
2. Create an R2 API token scoped to that bucket with object read/write access.
   Copy its Access Key ID and Secret Access Key when shown; do not use a global
   Cloudflare API key.
3. Find the account ID in the Cloudflare dashboard.
4. Connect a custom domain to the bucket for public image delivery and enable
   HTTPS. Set `R2_PUBLIC_BASE_URL` to that domain's base URL, without a trailing
   slash (for example, `https://images.example.com`). Public portfolio images
   must be readable from this URL. The application does not enable bucket
   listing or grant public write access.
5. Add the values to local `.env` and to the server-side environment settings
   for each deployment environment.

| Variable               | Required | Description                                                   |
| ---------------------- | -------- | ------------------------------------------------------------- |
| `R2_ACCOUNT_ID`        | Yes      | Cloudflare account ID used for the S3-compatible API endpoint |
| `R2_ACCESS_KEY_ID`     | Yes      | Bucket-scoped R2 API token access key                         |
| `R2_SECRET_ACCESS_KEY` | Yes      | Secret paired with the R2 access key                          |
| `R2_BUCKET_NAME`       | Yes      | Name of the destination bucket                                |
| `R2_PUBLIC_BASE_URL`   | Yes      | HTTPS custom-domain base URL for public image reads           |
| `R2_MAX_UPLOAD_BYTES`  | No       | Maximum image size in bytes; defaults to `10485760` (10 MiB)  |

Only JPEG, PNG, WebP, GIF, and AVIF files are accepted. The upload endpoint also
checks the image signature, not only the browser-provided MIME type. Object
keys are generated by the server and do not include the user-supplied filename.

## Image compatibility and migration

New Hero Reel and project thumbnail uploads use R2. Existing database image
URLs—including Cloudinary, static asset, and external URLs—are left unchanged
and continue to render as before. There is no mandatory bulk migration. To move
an existing image, upload it again in the relevant Admin Panel form and save
the setting or project so its stored URL is replaced with the new R2 URL.

## Deployment

### Render

Create a **Web Service** from the repository, not a Static Site.

- Build command: `npm install && npm run build:render`
- Start command: `npm run start`
- Runtime: Node.js 22 or newer

Add the app's existing server-side variables and all required R2 variables in
the Render service's Environment settings. Do not commit `.env`, put R2 values
in `VITE_*` variables, or expose them through client build settings. The
Render-specific build selects Nitro's Node server preset; the default
`npm run build` remains configured for the existing Vercel deployment.

### Vercel

Keep using `npm run build` and set all required database, authentication, and
R2 values as server-side Vercel project environment variables for Preview and
Production. Keep R2 credentials out of `VITE_*` variables.

Before deployment, verify that the custom domain is active and serves objects
from the configured bucket. Uploads require live MongoDB and R2 credentials and
a working public image domain; the repository build cannot verify those
external services.
